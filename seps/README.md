# Plug Specification Enhancement Proposals

Major contract/behavior changes and process changes use a SEP. Fixes and
clarifications use ordinary PRs. Copy [template.md](template.md), start the filename
with `0000`, then rename it to the actual proposal PR number once one exists.
Never invent a PR number, sponsor or approval. Owner/actual maintainers review on GitHub.

Statuses: `draft`, `in-review`, `accepted`, `final`, `rejected`, `withdrawn`,
`superseded`, `dormant`. Acceptance records a review decision; final behavior changes
also require implementation, specification updates and relevant regression tests.
Render pages with `npm run generate:seps`; validate with `npm run check:docs`.
